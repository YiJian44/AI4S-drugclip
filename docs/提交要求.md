本比赛要求选手提交可运行的 agent 代码。
1. 提交目标

选手提交的内容应当能够：

    在给定测试集目录上自动运行
    自主完成数据读取、策略执行、打分与结果生成
    输出标准格式的 result.zip
    在 result.log 中记录 agent 的主要运行过程

本比赛关注的不仅是最终分数，也关注 agent 是否真实进行了自主优化与自主决策。
2. 提交内容

选手需提交一个完整代码包，建议命名为：

teamname_trackname_submission.zip
解压后目录建议如下：

submission/
├── README.md
├── run.sh
├── requirements.txt
├── src/
│   ├── main.py
│   ├── agent/
│   ├── models/
│   ├── utils/
│   └── ...
├── configs/
│   └── default.yaml
├── scripts/
│   └── ...
└── assets/
​

3. 必需文件
3.1 README.md

必须包含以下内容：

    队伍名称
    赛道名称
    方法简介
    运行方式
    依赖说明
    输出文件说明
    是否使用外部模型或外部数据
    是否需要 GPU
    预估运行时间

3.2 run.sh

必须提供统一启动脚本，例如：

bash run.sh <input_dir> <output_dir>

其中：

    <input_dir>：组委会提供的测试集目录
    <output_dir>：选手程序输出目录

评测时将优先使用 run.sh 作为入口。
3.3 依赖说明

必须提供依赖文件，例如：

    requirements.txt
    或 environment.yml

若依赖特殊系统库、CUDA 环境或第三方工具，也必须在 README.md 中明确说明。
4. 输入与输出规范
4.1 输入

评测时，组委会将提供测试集目录，目录结构以官方发布的数据包为准。

选手代码应能够读取例如以下内容：

    manifest.jsonl
    tasks/<task_id>/task.json
    tasks/<task_id>/ligands.csv
    tasks/<task_id>/receptors/
    tasks/<task_id>/refs/

4.2 输出

程序运行完成后，必须在 <output_dir> 下生成：

result.zip

其中必须包含：

result.zip ​├── result.csv ​└── result.log
result.csv

格式必须为：

task_id,ligand_id,score

要求：

    每个 (task_id, ligand_id) 必须且只能出现一次
    所有任务必须完整覆盖
    score 为实数，分数越高表示排序越靠前

result.log

result.log 必须真实记录 agent 的运行过程，用于辅助判断其是否进行了真实的自主优化与自主决策。建议记录内容包括：

    初始化配置
    数据加载过程
    模型/策略选择过程
    多轮决策或迭代过程
    训练、微调、推理、重排序过程
    关键中间结果与异常信息
    最终结果生成过程

5.Agent 行为要求

选手提交的程序应体现 agent 的自主执行能力。允许的形式包括但不限于：

    基于规则的自主决策
    基于模型的自主打分与排序
    基于反馈的多轮优化
    多模块协作或多阶段 pipeline

但无论采用何种方式，程序都应在给定输入下独立完成任务，而不是仅提交离线预先写死的答案。
6.外部资源使用规则
6.1 允许

除官方提供的测试集外，选手可使用其他合法获取的外部资源增强方法能力，例如：

    外部公开数据
    预训练模型
    公共知识库
    合法开源工具与库

6.2 禁止

以下行为视为违规：

    使用官方测试集进行训练、微调或模型选择
    利用测试集标签、映射关系或其他泄漏信息恢复答案
    直接或间接构造 result.csv
    提交与日志不符的伪造运行结果
    其他经组委会认定为破坏公平性的行为

若发现违规，相关赛道成绩可能被置零，严重者可取消比赛资格。
7.API Key 与外部服务使用规范

    选手提交的代码中不得包含任何真实的 API Key、Access Token、Cookie、私有证书或其他敏感凭据。
    如程序需要调用外部 API 或模型服务，必须通过环境变量或配置占位符读取，不得将真实密钥硬编码在代码、脚本、配置文件或 README 中。
    选手需在 README.md 中明确说明所需的环境变量名称、用途及配置方式。
    若运行环境中未提供相应密钥，程序应能够明确报错退出，或自动切换到无需外部密钥的本地模式 / fallback 模式。
    不得在 result.log、标准输出、报错信息或其他日志中打印任何真实密钥或敏感认证信息。

8. 可复现性要求

选手提交的代码应尽量满足可复现性要求：

    固定随机种子（如适用）
    不依赖本地绝对路径
    不依赖未说明的私有文件
    不依赖交互式人工干预
    在统一环境中可直接启动

如果程序需要缓存、中间文件或模型权重下载，应在 README.md 中写明。
9.路径与目录要求

    代码中应尽量使用相对路径，而不是写死本地绝对路径。
    所有运行所需源码都必须包含在提交包中。
    不应依赖提交包之外的未说明目录结构。
    如程序需要额外参考资料，可放入单独目录并在 README.md 中说明用途。

10. 运行限制建议

选手应尽量控制程序复杂度与资源消耗。建议：

    支持单机自动运行
    避免必须人工中断或人工选择参数
    避免无限循环、阻塞等待或长时间无输出
    在日志中定期输出进度信息

11. 日志真实性要求

result.log 不仅用于调试，也用于审查 agent 行为。请注意：

    日志应与实际运行过程一致
    不应伪造训练过程、推理过程或决策过程
    不应仅输出极短模板化日志冒充真实执行
    组委会可能结合结果分布、日志内容与程序行为进行综合审查

若日志显示未真实进行自主优化，或与实际输出明显不一致，成绩可能被判为无效。
12.无效提交情形

以下情况可能导致提交无效：

    无法正常解压
    缺少必要文件
    入口脚本无法运行
    未生成 result.zip
    result.zip 中缺少 result.csv 或 result.log
    result.csv 格式错误
    任务覆盖不完整
    存在明显违规行为

13. 解释权

组委会保留对代码规范、运行结果、日志审查、违规认定及最终成绩的解释权。
